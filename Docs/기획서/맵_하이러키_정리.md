# 맵 하이러키 정리

## 증상

`Assets/Map/Map.prefab`의 `Tilemap/ground/dirt`, `Tilemap/ground/road` 아래가 `area1`, `area1 (1)`, `area2`, `area2 (1)`... 식으로 복사/붙여넣기 되며 같은 이름의 폴더가 여러 겹 중첩돼 있고, 그 안에 바닥 타일 639장, 건물 72개, 장식 61개, 자동차 12개가 뒤섞여 들어있어 하이러키가 중구난방이었다. 오브젝트 이름도 대부분 `area1_건물_04 (ChatGPT Image 2026년 7월 30일 오후 03_56_01-Photoroom (1)_0)` 처럼 AI 생성/배경제거 툴이 붙인 긴 원본 이름을 그대로 달고 있었다.

## 1차 시도 — 절반만 성공

`Assets/Editor/MapHierarchyOrganizerTool.cs`를 처음 만들었을 때는 이름에 `_건물_`/`_장식_`/`_자동차_` 태그가 있거나 `dirt`/`road`로 시작하는 스프라이트를 쓰는 것만 분류했다. 실행 결과 `바닥 1..576`, `건물 1..72`는 정리됐지만:

- `_장식_`/`_자동차_`, 도로 타일은 이름 변경 대상이 아니어서 그대로 남음
- **`Tilemap/ground/dirt` 밑에 `비닐하우스/건물`, `군용기지/건물`, `군용기지2/{바닥,건물}` 같은 서브폴더 130개가 미분류로 남음** — 이 오브젝트들은 정크 이름을 달고 있지만 `_건물_` 태그가 없고 dirt/road 스프라이트도 아니라 분류 규칙에 안 걸렸다
- 건물/장식 **자식**(스프라이트 조각, 콜라이더)의 ChatGPT 이름 485개는 애초에 손대는 범위가 아니어서 그대로 남음
- 건물을 `건물 N`으로 재이름하면서 `_건물_` 태그 자체가 사라져 **재실행해도 다시 분류가 안 되는(멱등하지 않은)** 구조였음

## 2차 시도 — 전체 재작성 (현재)

`MapHierarchyOrganizerTool.cs`를 스캔 범위·분류 규칙·자식 이름까지 전부 다시 짰다. `Zzinmak/맵 하이러키 정리 미리보기` / `Zzinmak/맵 하이러키 정리 적용` 메뉴는 그대로다.

**스캔 범위:** Map 루트 전체(`PortalSpawner`만 제외 — 게임 로직이 자식 인덱스로 참조하므로 절대 안 건드림). 더 이상 `Tilemap/ground/dirt`처럼 고정된 경로를 가정하지 않고, 재귀로 전체를 훑는다.

**분류 우선순위** (걸리면 그 지점에서 재귀 중단):
1. 이미 `카테고리 N` 형태인 이름 → 그 카테고리 (재실행 시 그대로 재수집 — 멱등성의 핵심)
2. 이름에 `_건물_`/`_장식_`/`_자동차_` 포함 → 해당 카테고리 (레거시 이름 호환)
3. **폴더 자체가 정확히 "건물"/"장식"/"바닥"/"도로"/"자동차"/"논"이면 그 직속 자식 전부를 그 카테고리로 본다** — `비닐하우스/건물`, `군용기지2/바닥` 같은 서브폴더를 잡아내는 규칙. Map 루트 바로 아래의 카테고리 그룹 자체도 이 규칙에 걸려서 "이미 들어있는 것들을 재수집"하는 것으로 자연스럽게 처리됨 → **1차 시도가 놓친 130개는 이 규칙으로 해결.**
4. SpriteRenderer 텍스처가 `dirt*`/`road*` → 바닥/도로
5. 위 어디에도 안 걸리면 중간 폴더로 보고 재귀

**6개 그룹**(`바닥`/`도로`/`건물`/`장식`/`자동차`/`논`)을 Map 루트 바로 아래에 두고, `SetParent(worldPositionStays: true)`로만 옮긴다 — **position/rotation/scale은 절대 건드리지 않는다** ([[이동_버벅임_수정]]의 격자 스냅 시도에서 위치를 건드렸다가 유기적으로 배치된 바닥이 뒤죽박죽 보이는 부작용이 있었던 걸 반복하지 않기 위함). `PortalSpawner`는 스캔 대상에서 아예 제외.

옮기고 나서 비어버린 `area*`/`비닐하우스`/`군용기지*`/`dirt`/`road`/`ground`/`Tilemap` 같은 중간 폴더(자식 없고 Transform 외 컴포넌트 없음)는 자동으로 삭제한다(적용 앞뒤로 두 번 실행 — 콜라이더 재배치로 마지막 하나가 비워지는 경우까지 처리).

**이름 재부여 (전체 6개 카테고리):** 화면 기준 왼쪽 위부터 오른쪽으로, 다 채우면 다음 줄로 내려가는 읽기 순서로 `바닥 1`, `도로 1`, `건물 1`, `장식 1`, `자동차 1`, `논 1`부터 새로 번호를 매긴다. 완벽한 격자 배치가 아니라서 스프라이트 높이 중간값의 60%를 "같은 줄" 판정 오차로 쓴다.

**자식(스프라이트 조각·콜라이더) 이름도 재귀적으로 정리한다** — `건물 5`처럼 카테고리 번호가 매겨진 오브젝트 밑을 다시 훑어서:
- 적을 막는 콜라이더(레거시 `fw`) → `건물 5_충돌`
- 안 막는 콜라이더(레거시 `DE`/`비닐 콜라이더`) → `건물 5_콜라이더`
- 그 외(스프라이트 등) → `건물 5_1`, `건물 5_2`...
- 같은 역할이 2개 이상이면 두 번째부터 `_충돌 2`, `_콜라이더 2`처럼 번호를 붙임
- 손자 이상도 같은 규칙으로 재귀 (부모 이름이 갱신된 뒤 적용되므로 순서 중요)

콜라이더를 **역할별로 이름을 구분**하는 이유: `Assets/Scripts/Environment/BuildingCollision.cs`가 이름으로 "적을 막는 콜라이더"를 판별한다(아래 참고). 전부 `콜라이더 N`으로 합쳐버리면 장식용 콜라이더까지 적을 막아버려 게임플레이가 바뀐다.

**콜라이더 재배치:** 건물/장식/자동차를 통째로 옮기므로 자식 콜라이더는 자동으로 같이 이동한다(143개 중 142개가 이미 정상적으로 자식 상태였음). 그 외 혼자 떨어져 있던 `Collider2D`(예: `Tilemap` 바로 밑의 `fw (1)` 1개)는 스프라이트 바운드 중심이 가장 가까운 건물/장식의 자식으로 자동 재배치한다.

### 연쇄 수정 — 이름-기반 판별 코드 동기화

콜라이더 이름을 바꾸면서, 이름으로 동작을 판별하던 다른 코드도 같이 고쳤다(안 그러면 적이 건물을 통과하는 버그가 남):

- **`Assets/Scripts/Environment/BuildingCollision.cs`** — `IsFootCollider`가 `_충돌` 접미사도 인식하도록 수정 (`Enemy.cs`/`EnemySpawner.cs`/`BossSpawner.cs`가 이 판별을 통해 적/보스의 건물 충돌을 처리한다).
- **`Assets/Editor/BuildingColliderTool.cs`** — `IsBuildingName`이 `건물 N` 패턴도, `IsFwName`이 `_충돌` 접미사도 인식하도록 수정. 이 툴이 새로 생성/이관하는 콜라이더 이름도 `fw` 대신 `<건물이름>_충돌`로 맞춤 — 안 그러면 이 툴을 다음에 실행할 때 옛날 이름 `fw`가 다시 생겨난다.

### 삭제

**`Assets/Editor/FloorTileAlignmentTool.cs`** 삭제 — [[이동_버벅임_수정]]에서 시도했다 롤백한 격자 스냅 접근이고, 대상 판별을 `dirt_05`/`road3_02` 스프라이트 이름으로 하는데 타일이 이제 `바닥 N`으로 재이름되어 이미 동작 불능이었다. 남겨두면 다음에 실수로 실행될 위험만 있어 제거.

## 이번 범위 밖 — 별도 확인 필요

건물/장식 루트 다수(약 302개)에 **Missing (Mono Script)** 컴포넌트가 붙어 있다 — guid `7db70e0ea77f5ac47a8f4565a9406397`를 참조하는데 `Assets` 안에 해당 `.meta`가 없다(과거 삭제된 스크립트로 추정). 하이러키 정리와 무관한 선행 이슈라 이번엔 안 건드렸음. Unity 인스펙터에서 확인 후 어떤 스크립트였는지 파악해 별도로 정리할 것.

## 적용 시 주의

반드시 `Map.prefab`을 프리팹 모드로 더블클릭해서 연 상태에서 실행할 것(아니면 에러 메시지만 뜨고 아무 것도 안 함). 적용 후 프리팹 모드에서 Ctrl+S로 저장해야 `Game.unity`/`2 SCENE.unity`가 공유하는 원본에 반영된다. 적용 후에는:
1. Scene 뷰에서 맵 외형이 적용 전과 똑같은지 확인 (위치를 안 건드렸으므로 픽셀 단위로 동일해야 함)
2. 같은 메뉴를 한 번 더 실행해서 "변경 없음"에 가깝게 나오는지 확인 (멱등성 확인)
3. `Game.unity`를 플레이해서 적/보스가 건물을 통과하지 못하는지 확인 (`_충돌` 판별이 실제로 동작하는지 — 이번 변경의 유일한 게임플레이 리스크)
