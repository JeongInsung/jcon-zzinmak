# 플레이어 이동 버벅임 수정

## 증상

플레이어를 이동시킬 때 화면이 미세하게 버벅였다. 바닥이 원인처럼 보였지만 실제 원인은 물리 보간 설정이었다.

## 원인

`Assets/Prefabs/Player.prefab`의 Rigidbody2D가 `Interpolate: None`이었다. 물리는 `Fixed Timestep 0.02`(50Hz)로 도는데 화면은 60Hz 이상으로 그려져서, 초당 약 10프레임은 플레이어 Transform이 직전 프레임과 완전히 동일한 위치에 머물렀다(계단식 이동). `CameraFollow`가 플레이어를 따라가므로, 화면상 실제로 크게 움직이는 건 바닥 스프라이트들이었고, 그 스크롤이 계단식으로 끊겨 보여서 "바닥 때문"으로 느껴진 것.

보조 원인:
- `CameraFollow` / `ExpDog` / `DroneController`가 `Vector3.Lerp(a, b, speed * Time.deltaTime)`로 프레임레이트에 의존하는 스무딩을 쓰고 있었다.
- `Application.targetFrameRate`가 설정되어 있지 않아 프레임 페이싱이 플랫폼/퀄리티 레벨마다 달랐다.
- `PlayerController.PlayFootstep`이 `AudioSource.PlayClipAtPoint`를 호출마다 GameObject를 생성/파괴하는 방식으로 써서, 걷는 동안만 초당 ~2회 오브젝트 churn이 발생했다.

## 수정 내용

1. **`Assets/Prefabs/Player.prefab`** — Rigidbody2D `Interpolate: None` → `Interpolate`. (`Extrapolate`는 방향 전환 시 오버슈트/스냅백이 나서 쓰지 않음. Fixed Timestep은 `0.02` 그대로 유지 — 보간이 모든 주사율에서 정확히 해결하므로 물리 스텝을 올릴 필요 없음.)
2. **`Assets/Scripts/Environment/MissionManager.cs`** — 보간이 켜지면 `player.position = ...`(Transform 직접 대입) 텔레포트가 깨진다. 보간 패스가 매 프레임 Transform을 덮어써서, 건물 입장/퇴장 시 이전 위치와 새 위치 사이를 한 스텝에 걸쳐 미끄러지듯 보간해버린다. 그래서 `TeleportPlayer(Vector3 destination)`를 추가: `Rigidbody2D.position`을 직접 옮기고, 그 순간만 `interpolation`을 `None`으로 껐다가 복구해서 보간 히스토리를 새 위치에서 다시 시작시킨다. `EnterBuilding()`/`ExitBuilding()`의 두 텔레포트 호출을 이 메서드로 교체.
   - **앞으로 플레이어를 순간이동시킬 일이 생기면 반드시 이 `MissionManager.TeleportPlayer` 패턴(또는 동일한 방식)을 쓸 것.** `Transform.position`을 직접 대입하면 이동 중 미끄러짐 버그가 재발한다.
3. **`Assets/Scripts/Core/GameManager.cs`** — `Awake()`에서 `QualitySettings.vSyncCount = 0; Application.targetFrameRate = 60;` 설정. 모바일에서 vSyncCount는 무시되고 targetFrameRate가 실질 상한이므로, 고주사율 폰이 발열로 프레임이 들쭉날쭉해지는 것을 방지.
4. **`Assets/Scripts/Player/CameraFollow.cs`** — 프레임 독립 스무딩으로 교체: `t = 1 - pow(1 - followSpeed * (1/60), deltaTime / (1/60))`. 인스펙터의 `followSpeed = 8` 값 의미는 그대로 유지되며(60fps에서 기존 `speed * deltaTime`과 수학적으로 동일), 다른 프레임레이트에서도 같은 반응을 유지한다. 덤으로 `Time.timeScale = 0`일 때 카메라가 완전히 정지하고, 프레임 스파이크 시 순간이동 대신 빠른 연속 보정이 된다.
5. **`Assets/Scripts/Progression/ExpDog.cs`**, **`Assets/Scripts/Combat/DroneController.cs`** — 동일한 프레임 독립 스무딩 공식 적용 (각각 `followSpeed=6`, `followLerpSpeed=6` 값 의미 그대로 유지).
6. **`Assets/Scripts/Player/PlayerController.cs`** — `Awake()`에서 `AudioSource`를 런타임에 붙여 캐싱(프리팹 수정 없음), `PlayFootstep`에서 `PlayOneShot` 사용. `PlayClipAtPoint`가 유발하던 걷기 중 GameObject 생성/파괴 오버헤드 제거.

## 손대지 않은 것

- **바닥 스프라이트 639장 / 맵 계층** — Tilemap 병합, CompositeCollider2D, SpriteAtlas 도입 안 함. 원인이 보간 미설정이었으므로 불필요.
- **PixelPerfectCamera(화면 픽셀 단위 스냅)** — 이 게임은 픽셀아트가 아니고(타일 위치가 임의 float, 비정수 스케일들) 화면 픽셀(약 1/119.5 유닛) 단위로 스냅을 걸면 플레이어 이동 자체가 눈에 보이게 뚝뚝 끊긴다. **아래 7번의 텍셀 스냅과는 다르다** — 저건 카메라의 "렌더링 위치"만 훨씬 더 촘촘한 텍스처 텍셀(1/100 유닛) 단위로 스냅하는 것이라, 움직임 부드러움에는 영향이 없다.
- **`ProjectSettings/TimeManager.asset`의 Fixed Timestep** — `0.02` 그대로.
- 씬 파일(`Game.unity`, `2 SCENE.unity`, `Intro.unity`)은 수정하지 않음.

## 후속 수정 — 바닥 타일 이음선이 기어다니는(seam crawl) 문제

이동 버벅임을 고친 뒤, 바닥 타일이 이어지는 경계에서 "선 같은 게 계속 움직인다"는 별도 신고가 있었다.

**원인:** `Assets/Map/바닥/dirt_05.png` 등 바닥 스프라이트는 Tilemap이 아니라 개별 스프라이트 쿼드로, 위치가 100 PPU 격자에 정확히 맞춰 배치돼 있지 않다(임의 float 좌표, 필터 모드 Bilinear, 밉맵 꺼짐). 인접한 두 타일이 서브픽셀 단위로 완벽히 맞물리지 않으면 그 경계에 아주 얇은 틈/겹침이 생기는데, 카메라가 매 프레임 연속적으로 미세한 소수 단위로 움직이다 보니 그 경계가 화면 픽셀 그리드에 걸리는 방식이 프레임마다 계속 바뀌어서 이음선이 "기어다니는(crawl)" 것처럼 보인다.

**수정:** `Assets/Scripts/Player/CameraFollow.cs`의 `LateUpdate` 맨 끝, `transform.position`에 대입하기 직전에 카메라의 렌더링 위치(x, y)만 바닥 텍스처의 텍셀 격자(100 유닛당 1텍셀)로 스냅한다:
```csharp
position.x = Mathf.Round(position.x * FloorTexelsPerUnit) / FloorTexelsPerUnit;
position.y = Mathf.Round(position.y * FloorTexelsPerUnit) / FloorTexelsPerUnit;
```
카메라의 부드러운 추종 로직(프레임 독립 스무딩)은 그대로 두고, 그 결과값을 텍셀 단위로만 반올림한다. 이음선이 화면에서 보이는 위치는 카메라가 텍셀 하나를 완전히 넘어갈 때만 바뀌게 되어, 매 프레임 계속 움직이던 크롤링이 사라진다. 스냅 단위가 워낙 촘촘해서(1/100 유닛 ≈ 화면상 1px 미만) 플레이어 이동이나 카메라 추종의 부드러움에는 체감상 영향이 없다 — 위에서 뺀 PixelPerfectCamera(화면 픽셀 단위)와는 스냅 단위 자체가 다르다.

**추가 수정 (텍셀 스냅만으로는 부족했음):** 텍셀 스냅은 이음선이 "매 프레임" 바뀌는 것만 줄였을 뿐, 반짝임 자체는 계속 남아 있었다. 근본 원인은 **Bilinear 필터링이 타일 경계에서 인접 텍셀 색을 섞어 그리는 방식** 자체였다 — 두 타일이 서브픽셀 단위로 완벽히 안 맞물려 있으면, Bilinear는 그 경계의 색을 매 프레임 다른 비율로 블렌딩해서 반짝이는 아티팩트를 만든다.

`Assets/Map/바닥/` 아래 바닥 텍스처 22장(`dirt_01/02/05`, `road3_01/02/03`, `road5_01/03/04` 및 각 변형 파일) 전부 `.meta`의 `filterMode`를 **`1`(Bilinear) → `0`(Point)** 로 변경했다. Point 필터는 경계에서 인접 텍셀을 섞지 않고 하나만 그대로 샘플링하므로, 블렌딩에서 나오던 반짝임이 근본적으로 사라진다. 이 게임은 100 PPU 텍스처가 화면에서 약 1.1~1.2배로 확대되는 수준(픽셀아트처럼 각지게 보일 정도로 축소되지 않음)이라, Point로 바꿔도 타일 내부의 이미지 품질 차이는 거의 안 보인다.

**적용 시 주의:** `.meta` 파일만 고친 것이라, 유니티 에디터가 텍스처를 다시 임포트해야 반영된다. 에디터가 포커스를 얻으면 보통 자동으로 감지해서 재임포트하지만, 안 되면 `Assets/Map/바닥` 폴더를 선택하고 우클릭 → Reimport.

**세 번째 시도 (Point 필터링으로도 해결 안 됨) — 스프라이트 메시 타입.** Point로 바꿔도 반짝임이 남아있어, 텍스처 색상 문제가 아니라 **메시(스프라이트 모양) 자체의 기하학적 틈**임을 확인했다. 22장 전부 `spriteMeshType: 1`(Tight)이었다 — Tight는 스프라이트의 투명 영역을 잘라내고 실루엣에 맞춰 메시를 생성하는데, `spriteExtrude: 1`(1px 확장)만으로는 소스 PNG 가장자리의 반투명/AI 생성 아트 특유의 부드러운 경계 픽셀을 완전히 못 덮는다. 그러면 인접 타일의 메시가 서브픽셀 단위로 안 맞물리는 실제 기하학적 틈이 생기고, 그 틈의 경계는 카메라가 움직이는 동안 안티에일리어싱(메시 가장자리 커버리지)이 매 프레임 달라져서 반짝인다 — 텍스처 필터 모드와는 무관한 원인.

`Assets/Map/바닥/` 22장 전부 `spriteMeshType`을 **`1`(Tight) → `0`(Full Rect)**로 변경했다. Full Rect는 알파(투명도) 내용과 무관하게 항상 스프라이트의 전체 사각형(320x320px = 3.2 유닛)을 메시로 사용하므로, 실루엣 트리밍에서 오는 틈이 사라진다.

**만약 이것도 안 된다면:** 남은 원인은 타일 자체의 **위치/스케일이 애초에 서로 정확히 안 맞물리게 배치**돼 있는 것이다(임의 float 좌표, 타일마다 다른 스케일 — Tilemap이 아니라 손으로/절차적으로 배치됨). 이건 메타파일 설정 몇 개로 고칠 수 없고 639장의 위치를 실제로 재계산/재배치해야 하는 훨씬 큰 작업이라 별도로 논의가 필요하다.

## 네 번째 시도 — 실제로 이것이었다: 타일 위치/스케일 자체가 격자에 안 맞음

Point 필터링 + Full Rect 메시로도 반짝임이 남아 있어서, 위 예측대로 `Assets/Map/Map.prefab` 안 바닥 타일 639장(`dirt_05` 576장, `road3_02` 62장, `road3_03` 1장)의 실제 Transform 값을 전수 조사했다.

**확인된 것:**
- 타일 위치가 3.2유닛(320px @ 100PPU) 격자에서 벗어난 정도가 거의 무작위로 -1.57~+1.56 유닛(최대 가능 범위 전체)에 고르게 분포 — 격자에 전혀 스냅되지 않은 채 손/절차적으로 배치됨.
- 607장은 `localScale (1,1,1)`, 8장은 좌우 반전용 `(-1,1,1)`로 정상이지만, **24장만 `(1.0226562,1,1)`**로 어긋나 있어 이 타일들은 폭이 3.2가 아니라 3.273유닛 — 이웃과 크기부터 안 맞음.
- `Map.prefab` 루트 자체도 비균등 스케일(`1.4681342, 1.7582927, 1.3849301`)이지만, 이건 맵 전체에 동일하게 적용되는 선형 변환이라 로컬 좌표에서 타일 경계가 맞으면 월드에서도 맞물린다(정사각형이 아니라 직사각형으로 보일 뿐). 그래서 **이 값은 건드리지 않았다** — 건드리면 바닥이 아닌 건물/장식/콜라이더까지 전부 위치가 틀어진다.

**수정:** `Assets/Editor/FloorTileAlignmentTool.cs` 추가. `Zzinmak/바닥 타일 정렬 미리보기` / `Zzinmak/바닥 타일 정렬 적용` 메뉴로 실행하며, `dirt_05`/`road3_02`/`road3_03` 스프라이트를 쓰는 SpriteRenderer만 대상으로:
1. `localPosition.x/y`를 3.2유닛 격자에 스냅 (z, 그리고 루트 스케일은 손대지 않음)
2. `localScale`의 절대값이 1이 아닌 것을 부호(좌우 반전 여부)만 유지한 채 1로 정규화

**적용 시 주의:** `Map.prefab`을 프리팹 모드로 더블클릭해서 열어놓고 실행해야 `Game.unity`/`2 SCENE.unity`가 공유하는 원본 프리팹에 반영된다(프리팹 모드가 아니면 현재 열린 씬의 오버라이드로만 저장됨 — `BuildingColliderTool`과 동일한 주의사항). 타일 위치가 최대 반 타일(±1.6유닛, 부모 스케일 적용 시 월드 기준 더 커짐) 이동할 수 있어 손으로 그려둔 길의 곡선 모양이 미세하게 각져 보일 수 있다 — 적용 후 반드시 Scene 뷰에서 육안으로 확인하고, 마음에 안 들면 git으로 되돌릴 것.

**실제로 적용한 결과 (2026-08-09):** 반짝임은 해결됐지만, 바닥 타일이 애초에 격자 정렬이 아니라 자연스러운 느낌을 위해 의도적으로 살짝씩 겹치거나 어긋나게(유기적으로) 배치돼 있었던 것으로 보인다 — 강제로 3.2유닛 격자에 스냅하니 일부 구간의 길/바닥 모양이 중구난방으로 보이는 부작용이 생겼다. 전체 되돌리기 대신, 어색해진 구간만 Scene 뷰에서 손으로 직접 재배치하는 쪽으로 진행하기로 함. **다음에 비슷한 격자-스냅 툴을 다시 쓸 일이 있으면, 먼저 일부 구간에만 적용해서 원래 배치가 격자 기반인지 유기적 배치인지부터 확인할 것.**

**후일담 — 툴 삭제:** 이후 [[맵_하이러키_정리]] 작업에서 바닥 타일이 `dirt_05 N` → `바닥 N`으로 재이름되면서, 이 툴의 대상 판별(`dirt_05`/`road3_02`/`road3_03` 스프라이트 이름 매칭)이 무의미해져 사실상 동작 불능이 됐다. 어차피 롤백된 접근이라 `Assets/Editor/FloorTileAlignmentTool.cs`를 삭제함.
