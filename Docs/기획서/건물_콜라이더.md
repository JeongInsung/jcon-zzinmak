# 건물 콜라이더 (fw)

## 작업 일자
2026-08-03

## 배경
`Assets/Map/Map.prefab`의 건물들은 SpriteRenderer만 있고 Collider2D가 없어서 플레이어(`Rigidbody2D` Dynamic + `CircleCollider2D`, `PlayerController.FixedUpdate`의 `body.MovePosition`으로 물리 이동)가 건물을 그냥 통과했음. 사용자가 큰건물(`area3_건물_06`) 뒤에 `fw`라는 이름의 보이지 않는 BoxCollider2D를 직접 넣어 막았고, 같은 방식을 장식품/차량을 제외한 건물 전체(`_ext_` 포함)에 확장 적용함.

과거(7/30) 한 번 같은 시도가 있었음 — `Assets/Map/큰건물 콜라이더.prefab`을 씬 루트에 월드 절대좌표로 배치했다가 `MapRoom`/`Map` 트랜스폼이 바뀌면서 건물과 어긋나 삭제됨(커밋 `89ef965` → `0091359`). 이번에는 fw를 **각 건물 GameObject의 자식**으로 넣어 건물이 옮겨져도 따라가게 했음.

## 변경 사항

### 1. `Assets/Editor/BuildingColliderTool.cs` (신규 에디터 툴)
메뉴: `Zzinmak/건물 콜라이더 일괄 생성`.

- **측정**: 기존에 손으로 넣은 fw들을 가장 가까운 건물에 매칭해서 실제 가로/두께 비율과 윗변 위치를 콘솔에 출력. 새 기본값을 정할 때 참고용.
- **이관**: 씬 루트에 있는 기존 fw를 대응 건물의 자식으로 옮기고, Transform 스케일 대신 `BoxCollider2D.size`/`offset`으로 크기를 표현하도록 변환. 월드 공간상 위치·크기는 그대로 유지됨. SpriteRenderer는 제거(안 보이게).
- **일괄 생성**: 이름에 `_건물_`이 포함된(단 `_장식_`/`_자동차_` 제외) 오브젝트를 전부 훑어서, 아직 `fw` 자식이 없는 건물에만 새로 생성. 건물(+ 하위 SpriteRenderer 전체)의 스프라이트 바운드를 기준으로 밑단에 얇은 콜라이더를 만듦. `SpriteRenderer 없음` → 시각적으로 안 보임.

기본 비율(사용자가 넣은 fw 6개 실측 기반):
- 가로 = 건물 폭 × **0.85**
- 두께 = 건물 높이 × **0.40**, 최소 **0.7 유닛**
- 막대 윗변 = 건물 스프라이트 밑변 (플레이어가 건물 위쪽으로는 지나갈 수 있고 발밑만 막힘)

레이어는 건물과 동일한 `Default(0)`를 그대로 사용 — 벽과 같은 방식이라 Player(8)·Enemy(9)는 막고 Projectile(10)은 통과함(Physics2D 매트릭스 그대로, 수정 안 함).

## 사용법
1. `Assets/Map/Map.prefab`을 더블클릭해서 **프리팹 모드로 연 상태**에서 실행할 것 — 그래야 `Game.unity`와 `2 SCENE.unity`가 함께 쓰는 원본 프리팹에 반영됨. 프리팹 모드가 아니면 현재 씬의 오버라이드로만 저장된다는 경고가 뜸.
2. 메뉴에서 `Zzinmak/건물 콜라이더 일괄 생성` 실행 → "기존 fw 측정" → "기존 fw를 건물 자식으로 이관" → "건물 콜라이더 일괄 생성" 순서로 버튼 클릭.
3. 결과는 실제 Hierarchy 오브젝트(런타임 스크립트 아님)이므로, 이후 인스펙터에서 개별 건물의 `fw` 자식을 골라 `BoxCollider2D.size`/`offset`을 손으로 미세조정 가능.

## 참고 / 주의
- **새로 맵에 건물을 추가할 때 이 툴을 다시 실행해야 함** — 자동으로 붙지 않음. `맵_그림자_시스템.md`의 ShadowCaster2D 경고와 같은 성격.
- 좀비(Enemy) 콜라이더는 프로젝트 원칙상 Trigger라서 물리적으로 막히지 않음 — 건물 안에 스폰돼도 별도 처리 불필요.
- `Assets/Scripts/Environment/MapBounds.cs`는 벽 4개만 참조하므로 이 콜라이더들과 무관.
