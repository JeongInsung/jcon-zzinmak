# 렉 원인 수정 및 좀비 이동 개선

## 작업 일자
2026-08-11

## 증상
좀비/터렛이 많아지면 유니티가 렉이 걸린다는 신고. 별개로, 좀비가 건물 콜라이더에 부딪히면 벽에 미끄러지듯 비비면서 플레이어에게 오는 문제도 있었음.

## 원인
1. `Assets/Scripts/Environment/BuildingCollision.cs`의 `IsFootCollider`가 콜라이더 히트마다 `Collider2D.gameObject.name`을 읽어 문자열 비교(EndsWith/StartsWith/Substring)를 했음. `GameObject.name`은 네이티브→매니지드 마샬링으로 호출마다 새 문자열을 할당하는데, 이 함수가 적/터렛의 물리 오버랩·레이캐스트 히트마다(매 FixedUpdate, 활성 적 수만큼) 호출돼 GC 스파이크로 인한 프레임 드랍의 유력 원인이었음.
2. `Assets/Scripts/Combat/TurretController.cs`의 `Update()`가 쿨다운 없이 매 프레임 `EnemyTracker.GetNearest`(O(활성 적 수) 순회)를 호출. `WeaponController`는 이미 `targetRefreshInterval`로 스로틀링돼 있었는데 터렛만 빠져 있었음.
3. (조사했으나 보류) `EnemyTracker.GetNearest(requireLineOfSight:true)` 경로가 레이어 필터 없이 맵 전체 콜라이더를 대상으로 레이캐스트함. `ProjectSettings/Physics2DSettings.asset`의 `m_LayerCollisionMatrix`가 이미 커스텀 설정돼 있어([[건물_콜라이더]] 참고 — Default가 Player/Enemy는 막고 Projectile은 통과), 건물 전용 레이어를 새로 만들면 이 매트릭스를 똑같이 맞춰야 발사체/충돌 동작이 안 깨짐. 프리팹 139개 콜라이더 재할당까지 겹쳐 리스크 대비 되돌리기 어려워 사용자 요청으로 보류.
4. 좀비 이동(`Enemy.cs`의 `ResolveMovement`)이 X축/Y축을 따로 막힘 판정해서 이동시키는 방식이었음. 벽에 각도를 갖고 접근하면 막힌 축만 0이 되고 나머지 축으로만 계속 이동해서, 벽에 비비듯 미끄러지는 것처럼 보였음.

## 수정 내용
1. **`BuildingCollision.cs`** — `IsFootCollider` 결과를 `Dictionary<int, bool>`(콜라이더 `GetInstanceID()` 기준)로 캐싱. 건물 콜라이더는 씬 로드 후 이름이 바뀌지 않는 정적 지오메트리라 매 호출 재계산할 필요가 없음 — 문자열 할당이 콜라이더당 최초 1회만 발생.
2. **`TurretController.cs`** — `targetRefreshInterval`(기본 0.1초) 필드와 `currentTarget` 캐시를 추가해 `WeaponController`와 동일한 방식으로 타겟 탐색을 스로틀링.
3. **`Enemy.cs`** — `ResolveMovement`를 X/Y축 개별 판정 대신 "직진 방향 우선 시도 → 막히면 15도 단위로 좌우 각도를 최대 150도까지 넓혀가며 뚫린 방향 탐색" 방식으로 교체. 평소(안 막힘)는 오버랩 체크 1회로 기존과 동일한 비용이고, 막힌 좀비만 추가 각도 스캔(뚫리는 각도 찾는 즉시 중단)이 발생.

## 손대지 않은 것
- 레이어 기반 라인오브사이트 필터링(원인 3번) — 위 이유로 사용자 요청에 따라 보류.
- 프로파일러 실측 없이 코드 리딩만으로 진단함 — 실제 개선폭은 Window > Analysis > Profiler로 GC.Alloc/Physics2D.Raycast 항목을 직접 확인 필요.
- 오디오 임포트 압축 설정은 미확인.
